# 會議錄影工具

網頁版的螢幕錄影 + 錄音工具，專門用來錄 Webex / Zoom / Teams 這類會議軟體。
全部在自己電腦上跑，影像與聲音不會上傳到任何地方。

設計主軸只有一句話：**不要錄完才發現沒錄到。**

---

## 網址

**https://meeting-recorder.etfswing-site.workers.dev/**（Cloudflare，主要網址）

備用：https://city2243.github.io/meeting-recorder/ （GitHub Pages，同一份內容）

用 Chrome 或 Edge 打開就能用，不用安裝、不用登入。
第一次打開時，頁面最上面會自己跑一輪環境檢查，告訴你這台電腦做得到什麼。

> 影像和聲音完全在你的瀏覽器裡處理，不會上傳到 GitHub 或任何地方。
> 這個網站只是把程式碼送到你的瀏覽器而已。

也可以離線用：把整個資料夾抓下去，雙擊 `啟動錄影工具.bat`，
它會起一個本機伺服器並開啟同一個頁面。

## 操作四步

### 1. 設定

- **存檔資料夾**：錄完要放哪裡。**選過一次就記住了**，下次打開直接沿用，
  不用每次重選。瀏覽器有時候會要你再確認一次權限，那時按「繼續用『XXX』」就好，
  不會再跳選檔視窗。不想記了就按「忘記這個資料夾」。
- **麥克風**：要不要錄自己的聲音。只想錄會議內容就選「不錄麥克風」。
- **畫質**：一般會議選 `1080p / 15fps` 就夠了，文字很清楚，一小時約 1.2 GB。
- **預計會議長度**：只用來事先算磁碟空間夠不夠。
- **自動開始**：勾了之後，只要檢查沒有紅色項目就會倒數 3 秒自動開錄，
  來不及的話按「先等一下」可以取消。會議快開始時很有用。

所有設定（含畫質、麥克風、保險機制）都會記住，下次打開就是上次的樣子。

### 2. 開錄前檢查（最重要的一步）

按「選擇畫面並開始檢查」後，Chrome 會跳出分享視窗。

> **一定要選「整個畫面」，並勾選左下角的「同時分享系統音訊」。**
>
> Zoom / Webex / Teams 是獨立的桌面程式，不是網頁分頁。選「視窗」抓不到任何聲音——
> 這是「錄完發現沒聲音」最常見的原因。

接著工具會自動跑九項檢查，其中最關鍵的是「試錄並解碼驗證」：
它用**等一下真正要錄的那條訊號**試錄四秒，再把成品解碼回來，確認裡面
真的有影像、真的有聲音波形。不是看設定有沒有打勾，是看成品。

有紅色項目時，「開始錄製」按鈕會鎖住。

### 3. 錄製中

儀表板上有四個即時數字：畫面 fps、系統音音量、麥克風音量、已安全寫入磁碟的容量。
出問題時會**同時**跳紅色橫幅、發出提示音、跳桌面通知、閃動分頁標題——
因為你那時候正盯著會議視窗，不會看著這一頁。

會盯的狀況：

| 狀況 | 反應 |
|---|---|
| 畫面超過 6 秒沒有新畫格 | 紅色警報 |
| 有人按了 Chrome 的「停止共用」 | 紅色警報，聲音繼續錄，可按「重新接上畫面」接成新的一段 |
| 超過 15 秒沒有新資料寫進磁碟 | 紅色警報 |
| 會議聲音連續兩分鐘沒有任何波形 | 黃色提醒 |
| 每 5 分鐘一次深度健檢 | 偷偷試錄 1.2 秒再解碼，確認編碼管線還活著 |

### 4. 完成與驗證

停止後會自動做一輪驗證並顯示結果：檔案大小、可否播放、影片長度、
**聲音是不是一片數位靜音**、靜音佔比、最長連續靜音、平均 fps。
另外會存一份「健康紀錄.txt」，裡面有整場的事件與檢查結果。

最後自己拉一下播放器，中間和最後各看一眼，確認整段都在。

## 用 iPhone 開會、電腦在旁邊錄

**iPhone 自己錄不到會議的聲音。** iOS 不讓任何 App 取得通話音訊 —— 內建螢幕錄影錄不到，
第三方 App 走同一套 ReplayKit 管線，一樣錄不到。這是 Apple 刻意擋的，沒有軟體解法。

可行的做法是**讓電腦也加入同一場會議，靜音待在旁邊錄**。手機負責你講話，
電腦收到的是會議伺服器送來的完整音訊，品質跟你在電腦上開會一樣好。

### 出門前照這個做

1. **先把電腦的電源設定改掉。**設定 → 系統 → 電源與電池 → 螢幕與睡眠 →
   「插電時，讓裝置睡眠」設為**永不**。電腦睡著錄影就停了。（螢幕關掉沒關係。）
2. 用 Chrome 開會議的**網頁版**加入會議，**麥克風關、鏡頭關**（用另一個名字入會，避免跟手機那邊撞）。
3. 另開一個分頁到 https://meeting-recorder.etfswing-site.workers.dev/
4. 「要錄什麼」選 **「瀏覽器裡的會議」**。
5. 勾 **「錄的時候電腦不要把聲音放出來」** —— 不勾的話電腦喇叭會放出會議聲音，
   被手機麥克風收回去造成回授。
6. 勾 **「開啟無人看管保護」**，設好最長時數。建議也勾「連續靜音 N 分鐘就收檔」，
   會議散了它就會自己收檔存好。
7. 按「選擇分頁並開始檢查」→ 在分享視窗切到 **「Chrome 分頁」** → 挑會議那個分頁 →
   **勾「同時分享分頁音訊」**。
8. 九項檢查通過後按「開始錄製」。
9. **走之前確認兩件事**：左上角紅點在閃、「已安全落地」的數字每隔幾秒在增加。
10. 回來時檔案已經在你選的資料夾裡（如果會議還沒散，就自己按停止）。

### 無人看管時它會自己做的事

| 情況 | 反應 |
|---|---|
| 連續靜音超過設定的分鐘數 | 判定會議結束，自動收檔、驗證、存進資料夾 |
| 達到最長錄製時數 | 自動收檔存好，不會錄整晚把空間吃光 |
| 資料停止寫入／錄影器停擺／寫檔失敗 | 自動收檔，保住已經錄到的部分 |
| **畫面卡住** | **不會自動停** —— 那時聲音通常還在錄，為了畫面停掉整場會賠更多 |

⚠ **鎖定螢幕（Win+L）我沒有實測過。**分頁擷取不依賴螢幕繪製，理論上不會中斷，
但第一次用之前建議先做一次 10 分鐘的試驗確認。

## 同時錄多場（實測版）

**https://meeting-recorder.etfswing-site.workers.dev/multi**

一場抓一個**瀏覽器分頁**。分頁擷取拿到的音訊只有那個分頁的，所以每場都是乾淨的獨立音軌，
逐字稿不會被別場的聲音污染。

三個前提：

1. **會議要用網頁版參加。**桌面程式（Zoom / Webex 安裝版）的聲音只存在於整台電腦的混音裡，
   多場一定會糊在一起，這是瀏覽器層面的限制，繞不過去。
2. **選分頁時一定要勾「分享分頁音訊」**，沒勾會被檢查擋下來。
3. **預設不錄麥克風。**你的麥克風會同時收到所有場次的喇叭聲，混進去只會讓每一軌都變髒。建議戴耳機。

每場輸出兩個檔：`<場次編號>_<你取的名字>.webm`（影像＋聲音）和 `..._音訊.webm`（純音訊，
直接拿去跑逐字稿，不用再從影片抽）。另外會存一份 `..._多場實測報告.txt`，
裡面有每場的 fps 分布（前景／背景分開統計）、靜音佔比、心跳延遲與完整事件紀錄。

錄製中有一顆「標記這一刻」，按下去會在所有場次的紀錄裡留一個時間戳 —— 做壓力測試時
用來標「我現在把分頁切到背景了」。

**四場的完整操作教學直接寫在那一頁上**（開始之前 4 條、正式步驟 10 步、最容易出錯的 4 件事），
不用對照文件，照著頁面按就好。

### 合成訊號實測（2026-09-24，非真實會議）

| 場數 | 結果 |
|---|---|
| 2 場 720p15 | 全部驗證通過，兩場都穩在 15 fps，心跳最大延遲 1 ms |
| 4 場 720p15 | 全部驗證通過，四場都穩在 15 fps，心跳最大延遲 14 ms |

⚠ 這是用畫布合成訊號測的，比真實分頁擷取輕。真實會議還要加上 Zoom/Webex 自己的
編解碼負載，**真正的上限要拿真的會議測才算數**。

## 當機了怎麼辦

錄製過程中，資料是**每兩秒直接寫進磁碟並立刻 flush**，不是先堆在記憶體裡。
所以就算瀏覽器崩潰、電腦當機、停電，已經錄到的部分都還在。

下次打開工具頁面，最上方會出現「上次留下來的錄影檔」，按「另存到資料夾」就能拿回來。

如果那個檔案播放器拉不動進度條，用 `tools\修復錄影檔.bat` 重建索引（不會重新壓縮、畫質不變）。

| 檔案 | 用途 |
|---|---|
| `轉成MP4.bat` | 把 .webm 轉成通用的 .mp4（會重新壓縮，一小時的影片要等幾分鐘） |

`D:\Codex\doctor-video-pipeline-fast\node_modules\ffmpeg-static\ffmpeg.exe`，
換電腦的話要打開 .bat 改掉第一行的路徑。

## 英文版（中文／英文切換）

每一頁頂欄右邊都有「中文｜EN」切換鈕，按了立刻換，**錄影中切換也不會中斷錄影**。
選擇會記住；第一次來、瀏覽器語言不是中文的訪客，預設就是英文。

英文模式下，連產出的東西也是英文：

| 中文模式 | 英文模式 |
|---|---|
| `會議錄影_20260924_1430.webm` | `Meeting_20260924_1430.webm` |
| `…_音訊備份.webm` | `…_audio-backup.webm` |
| `…_健康紀錄.txt` | `…_health-log.txt` |
| `…_第2段` | `…_part2` |

條款頁的英文版僅供閱讀方便，內容有歧義時以中文版為準（頁面上有註明）。

### 之後改了介面文字，英文要怎麼跟上

翻譯是「顯示層」做的：程式裡照樣寫中文，頁面顯示時才換成英文。
新增或改了中文字串，英文模式就會看到那段沒翻（直接露出中文），照這三步補：

1. `node tools/extract_i18n.mjs i18n/units.json` —— 重新抽出所有中文字串
2. 只翻新增的那幾段，補進 `i18n/en.json`
3. `python tools/build_i18n.py` —— 會檢查沒漏翻、譯文沒殘留中文、`{1}` 佔位數量一致，全過才產出 `js/i18n-en.js`

## 多場版當機了怎麼辦

多場版開頁時，最上方會出現「上次留下來的錄影檔」，列出當機或關頁時還在錄的每一場（用原本的會議名稱）。
標「尚未匯出」的按「另存到資料夾」拿回來；確認資料夾裡的檔案能播之後，可以按「清除已匯出過的暫存檔」釋放空間。

錄製中某一場的分頁被關掉、或按了「停止共用」，那一場會在 3 秒後自動收檔保存，其他場照常錄。

## 已知限制

- **只能用 Chrome 或 Edge。** Firefox 抓不到 Windows 的系統音訊，Safari 不支援。
- **必須從網址開啟，不能用滑鼠雙擊 `index.html`。** 瀏覽器只在安全來源
  （https 或 localhost）下開放螢幕擷取與持久寫檔，`file://` 不算。
- **不能放在 iframe 裡。** 瀏覽器的權限政策禁止嵌入頁面擷取螢幕，
  所以這個工具做成 claude.ai artifact 是不會動的（已實測）。
- **錄的是整個螢幕。** 錄製期間跳出來的私人訊息（LINE、Outlook 通知）都會被錄進去。
- 錄製他人會議前請先取得對方同意。

## 程式結構

```
index.html              介面
app.css                 樣式
js/app.js               主流程：設定 → 檢查 → 監看 → 驗證匯出
js/media.js             畫面/麥克風擷取、混音、畫格與音量量測
js/checks.js            三道關卡：開錄前試錄驗證、錄製中深度健檢、錄完驗證
js/storage.js           持久寫檔、救援、串流匯出
js/opfs-worker.js       實際寫磁碟的 worker（sync access handle，寫完就 flush）
js/ticker-worker.js     不受背景分頁節流的心跳
js/i18n.js              中文／英文切換（顯示層翻譯、切換鈕、英文檔名）
js/i18n-en.js           英文翻譯表（由 tools/build_i18n.py 產生，不要手改）
```

### 三個踩過的坑（改動前先看這裡）

1. **不要用 `requestVideoFrameCallback` 數畫格。**
   分頁被蓋住時它完全不會觸發，而使用者錄會議時這個分頁本來就是被蓋住的，
   watchdog 會整場誤報。改用 `MediaStreamTrackProcessor` + `getVideoPlaybackQuality()`
   兩個獨立感測器，任一有進展就算畫面活著。

2. **驗證聲音時不要設「檔案要夠大才驗」的門檻。**
   Opus 會把數位靜音壓到只剩幾百 bytes，設門檻等於在「真的沒錄到聲音」時
   自動跳過檢查。曾經因為這個 bug 讓全靜音的錄影通過驗證。
   現在用兩條獨立線索判斷：解碼後的峰值，以及檔案大小相對名目碼率的比例。

3. **不要用 `'createSyncAccessHandle' in FileSystemFileHandle.prototype` 判斷能力。**
   那個方法只掛在 Worker scope，主執行緒查永遠是 false。改成實際寫一個測試檔驗證。

4. **翻譯改屬性（placeholder 等）時，一定要記得「上次是我自己寫的」。**
   `setAttribute` 就算寫入一樣的值也會觸發 MutationObserver；某段沒被翻到時，
   它會「翻 → 觸發 → 再翻」無限循環，整頁卡死（多場版英文模式曾因此凍住）。
   `js/i18n.js` 的 `wroteAttr` 就是這道防護，不要拿掉。

5. **開錄前不要 `await` 任何會跳詢問的權限（例如通知）。**
   Chrome 會跳出詢問泡泡，使用者沒回答之前錄影就一直不開始。多場版曾因此每按一場都排隊等，
   每場開頭少錄 1–7 秒，而且畫面上的計時也從晚開始算，完全看不出來。先開錄，再在背景問。

6. **分頁內容靜止時 Chrome 不送新畫格，不是故障。**
   真的分頁擷取實測：靜止的分頁 2.2 秒只來 1 張、錄製中約每秒 1 張。以前開錄前檢查把這判成失敗，
   會議還沒開始（等候畫面）的分頁永遠過不了檢查。只有「單一視窗」來源停格才代表視窗被最小化。
