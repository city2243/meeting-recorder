# 會議錄影工具

網頁版的螢幕錄影 + 錄音工具，專門用來錄 Webex / Zoom / Teams 這類會議軟體。
全部在自己電腦上跑，影像與聲音不會上傳到任何地方。

設計主軸只有一句話：**不要錄完才發現沒錄到。**

---

## 網址

**https://city2243.github.io/meeting-recorder/**

用 Chrome 或 Edge 打開就能用，不用安裝、不用登入。
第一次打開時，頁面最上面會自己跑一輪環境檢查，告訴你這台電腦做得到什麼。

> 影像和聲音完全在你的瀏覽器裡處理，不會上傳到 GitHub 或任何地方。
> 這個網站只是把程式碼送到你的瀏覽器而已。

也可以離線用：把整個資料夾抓下去，雙擊 `啟動錄影工具.bat`，
它會起一個本機伺服器並開啟同一個頁面。

## 操作四步

### 1. 設定

- **存檔資料夾**：錄完要放哪裡。建議先選，不然只能用瀏覽器下載的方式拿檔案。
- **麥克風**：要不要錄自己的聲音。只想錄會議內容就選「不錄麥克風」。
- **畫質**：一般會議選 `1080p / 15fps` 就夠了，文字很清楚，一小時約 1.2 GB。
- **預計會議長度**：只用來事先算磁碟空間夠不夠。

### 2. 開錄前檢查（最重要的一步）

按「選擇畫面並開始檢查」後，Chrome 會跳出分享視窗。

> **一定要選「整個畫面」，並勾選左下角的「同時分享系統音訊」。**
>
> Zoom / Webex / Teams 是獨立的桌面程式，不是網頁分頁。選「視窗」抓不到任何聲音——
> 這是「錄完發現沒聲音」最常見的原因。

接著工具會自動跑九項檢查，其中最關鍵的是「試錄並解碼驗證」：
它用**等一下真正要錄的那條訊號**試錄四秒，再把成品解碼回來，確認裡面
真的有影像、真的有聲音波形。不是看設定有沒有打勾，是看成品。

有紅色項目時，「開始錄製」按鈕會鎖住。

### 3. 錄製中

儀表板上有四個即時數字：畫面 fps、系統音音量、麥克風音量、已安全寫入磁碟的容量。
出問題時會**同時**跳紅色橫幅、發出提示音、跳桌面通知、閃動分頁標題——
因為你那時候正盯著會議視窗，不會看著這一頁。

會盯的狀況：

| 狀況 | 反應 |
|---|---|
| 畫面超過 6 秒沒有新畫格 | 紅色警報 |
| 有人按了 Chrome 的「停止共用」 | 紅色警報，聲音繼續錄，可按「重新接上畫面」接成新的一段 |
| 超過 15 秒沒有新資料寫進磁碟 | 紅色警報 |
| 會議聲音連續兩分鐘沒有任何波形 | 黃色提醒 |
| 每 5 分鐘一次深度健檢 | 偷偷試錄 1.2 秒再解碼，確認編碼管線還活著 |

### 4. 完成與驗證

停止後會自動做一輪驗證並顯示結果：檔案大小、可否播放、影片長度、
**聲音是不是一片數位靜音**、靜音佔比、最長連續靜音、平均 fps。
另外會存一份「健康紀錄.txt」，裡面有整場的事件與檢查結果。

最後自己拉一下播放器，中間和最後各看一眼，確認整段都在。

中途重新接過畫面的話，會多出 `_第2段`、`_第3段`。

## 當機了怎麼辦

錄製過程中，資料是**每兩秒直接寫進磁碟並立刻 flush**，不是先堆在記憶體裡。
所以就算瀏覽器崩潰、電腦當機、停電，已經錄到的部分都還在。

下次打開工具頁面，最上方會出現「上次留下來的錄影檔」，按「另存到資料夾」就能拿回來。

如果那個檔案播放器拉不動進度條，用 `tools\修復錄影檔.bat` 重建索引（不會重新壓縮、畫質不變）。

## 附的小工具（`tools` 資料夾）

| 檔案 | 用途 |
|---|---|
| `轉成MP4.bat` | 把 .webm 轉成通用的 .mp4（會重新壓縮，一小時的影片要等幾分鐘） |
| `修復錄影檔.bat` | 播放器讀不出長度、拖不動進度條、錄到一半當機時用 |
| `合併分段錄影.bat` | 把 `_第2段` `_第3段` 接成一個檔 |

這三個都需要 ffmpeg。目前設定的路徑是
`D:\Codex\doctor-video-pipeline-fast\node_modules\ffmpeg-static\ffmpeg.exe`，
換電腦的話要打開 .bat 改掉第一行的路徑。

## 已知限制

- **只能用 Chrome 或 Edge。** Firefox 抓不到 Windows 的系統音訊，Safari 不支援。
- **必須從網址開啟，不能用滑鼠雙擊 `index.html`。** 瀏覽器只在安全來源
  （https 或 localhost）下開放螢幕擷取與持久寫檔，`file://` 不算。
- **不能放在 iframe 裡。** 瀏覽器的權限政策禁止嵌入頁面擷取螢幕，
  所以這個工具做成 claude.ai artifact 是不會動的（已實測）。
- **錄的是整個螢幕。** 錄製期間跳出來的私人訊息（LINE、Outlook 通知）都會被錄進去。
- 錄製他人會議前請先取得對方同意。

## 程式結構

```
index.html              介面
app.css                 樣式
js/app.js               主流程：設定 → 檢查 → 監看 → 驗證匯出
js/media.js             畫面/麥克風擷取、混音、畫格與音量量測
js/checks.js            三道關卡：開錄前試錄驗證、錄製中深度健檢、錄完驗證
js/storage.js           持久寫檔、救援、串流匯出
js/opfs-worker.js       實際寫磁碟的 worker（sync access handle，寫完就 flush）
js/ticker-worker.js     不受背景分頁節流的心跳
```

### 三個踩過的坑（改動前先看這裡）

1. **不要用 `requestVideoFrameCallback` 數畫格。**
   分頁被蓋住時它完全不會觸發，而使用者錄會議時這個分頁本來就是被蓋住的，
   watchdog 會整場誤報。改用 `MediaStreamTrackProcessor` + `getVideoPlaybackQuality()`
   兩個獨立感測器，任一有進展就算畫面活著。

2. **驗證聲音時不要設「檔案要夠大才驗」的門檻。**
   Opus 會把數位靜音壓到只剩幾百 bytes，設門檻等於在「真的沒錄到聲音」時
   自動跳過檢查。曾經因為這個 bug 讓全靜音的錄影通過驗證。
   現在用兩條獨立線索判斷：解碼後的峰值，以及檔案大小相對名目碼率的比例。

3. **不要用 `'createSyncAccessHandle' in FileSystemFileHandle.prototype` 判斷能力。**
   那個方法只掛在 Worker scope，主執行緒查永遠是 false。改成實際寫一個測試檔驗證。
